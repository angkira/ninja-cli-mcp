# Docker Quickstart

Ninja MCP `1.0.1` provides a non-root Python 3.12 image and a Compose file
with four opt-in profiles: `coder`, `researcher`, `secretary`, and `agent`.
Normal users should use the installer TUI. Environment variables described
below are headless overrides for CI and scripted deployments.

## TUI Installer

From a checkout, run the normal installer and select the Docker target:

```bash
./install.sh
```

The first TUI question selects Docker mode. The prompts then collect:

- an existing absolute workspace directory;
- one or more service profiles;
- a unique host port for each selected profile;
- whether to build the image and start containers;
- optional runtime API credentials.

The default ports are `8100` (coder), `8101` (researcher), `8102` (secretary),
and `8103` (agent). Ports must be unique and within `1024..65535`; published
ports bind to `127.0.0.1`.

The generated project is stored at:

```text
~/.config/ninja-mcp/docker/
```

It contains `.env` without API secrets, a source/Compose directory when the
installer had to clone the source, and the executable `ninja-mcp-docker`
wrapper. A symlink is placed at `~/.local/bin/ninja-mcp-docker` when that path
does not already exist.

## Make Wrappers

Normal users should run `make install` from a checkout and choose Native or
Docker in the first TUI question. Do not run `make docker-up` before the TUI
has generated the Docker configuration. The Make targets read the generated
`~/.config/ninja-mcp/docker/.env` and select a Compose profile without putting
API secrets in Make arguments.

| Goal | Command |
| --- | --- |
| Interactive installer | `make install` |
| Resolve configuration only | `make docker-config PROFILE=coder` |
| Build an image | `make docker-build PROFILE=coder IMAGE=ninja-mcp:local-1.0.1` |
| Start a profile | `make docker-up PROFILE=coder COMPOSE_PROJECT_NAME=ninja-mcp` |
| Show status or follow logs | `make docker-status` or `make docker-logs` |
| Stop services | `make docker-down` |
| Remove volumes explicitly | `make docker-clean` |

Use `make help` for the full installation, quality, and release wrapper list.

## Wrapper Lifecycle

```bash
ninja-mcp-docker start
ninja-mcp-docker status
ninja-mcp-docker logs
ninja-mcp-docker config
ninja-mcp-docker stop
```

`start` runs `docker compose up -d` with every selected `--profile`.
`stop` runs `docker compose down`; `logs` follows logs; `config` prints the
resolved Compose configuration. The installer builds by default but does not
start containers unless the TUI start prompt is confirmed or
`NINJA_DOCKER_START=1` is set.

## Headless Overrides

Use these only when prompts are not suitable. The Make target
`make install-headless` is a clearly named internal wrapper for this supported
environment override; `--headless` is not a public `install.sh` option:

```bash
NINJA_DOCKER_WORKSPACE="$PWD" \
NINJA_DOCKER_PROFILES=researcher,secretary \
NINJA_DOCKER_RESEARCHER_PORT=18101 \
NINJA_DOCKER_SECRETARY_PORT=18102 \
NINJA_DOCKER_NONINTERACTIVE=1 ./install.sh
```

Supported settings include `NINJA_DOCKER_WORKSPACE`,
`NINJA_DOCKER_PROFILES`, `NINJA_DOCKER_*_PORT`,
`NINJA_DOCKER_CONFIG_DIR`, `NINJA_DOCKER_BUILD`, and
`NINJA_DOCKER_START`. `--auto` does not replace the Docker prompts; use
the internal `NINJA_DOCKER_NONINTERACTIVE=1` backend override for a scripted
invocation.

The image tag generated by the installer is `ninja-mcp:local-1.0.1`.

## Compose Profiles and Ports

Compose has no default services. Select profiles explicitly:

```bash
docker compose --profile agent run --rm agent analyze --repo-root /workspace
docker compose --profile researcher up --build
```

Each HTTP/SSE service listens inside the container on its fixed port and is
published to the selected localhost port. The SSE endpoints are `/sse` and
`/messages`; healthchecks probe `/sse`.

| Profile | Container port | Default host port | Workspace access |
| --- | ---: | ---: | --- |
| `coder` | 8100 | 8100 | read-write |
| `researcher` | 8101 | 8101 | read-only |
| `secretary` | 8102 | 8102 | read-only |
| `agent` | 8103 | 8103 | read-write by default |

The `agent` TUI prompt can choose read-only workspace access. The generated
Compose environment controls this as `NINJA_DOCKER_AGENT_ACCESS=ro|rw`.

## Credentials and Volumes

API keys are runtime inputs, not image contents. Export them before `start` or
point `NINJA_DOCKER_RUNTIME_ENV_FILE` at a user-owned untracked env file:

```bash
export OPENROUTER_API_KEY='...'
ninja-mcp-docker start
```

The TUI can write a protected runtime file at
`~/.config/ninja-mcp/docker/runtime.env` with mode `0600`. The generated
`.env` intentionally contains no secret values. `NINJA_CREDENTIAL_PASSWORD`
can be supplied for headless encrypted credentials.

The Compose project mounts only the explicit workspace and two named volumes:

- `ninja-config` at `/home/ninja/.ninja`;
- `ninja-cache` at `/home/ninja/.cache/ninja-mcp`.

Coder worktrees remain in the cache volume. The image runs as user `ninja`,
does not use privileged mode, does not mount `$HOME` or `docker.sock`, and does
not copy host-authenticated `claude`, `junie`, `opencode`, or `aider` state.
Host-authenticated CLIs therefore require a deliberately extended image or a
provider/API-backed operator inside the container.

## Manual Image Use

For a one-shot API-backed command:

```bash
docker run --rm -v "$PWD:/workspace:ro" ninja-mcp:1.0.1 \
  agent analyze --repo-root /workspace
```

## Troubleshooting

- **Docker is not found:** install Docker Engine and Compose v2, then rerun the
  installer.
- **Workspace rejected:** use an existing absolute directory, not a relative
  path.
- **Port validation fails:** selected host ports must be unique and between
  `1024` and `65535`; check whether a port is already occupied.
- **No service starts:** inspect `NINJA_DOCKER_PROFILES` and run
  `ninja-mcp-docker config`.
- **Authentication fails:** export the needed runtime key or configure the
  provider inside the image; host login state is intentionally not mounted.
- **Stale setup:** inspect the generated `.env`, then run `stop`, adjust the
  file, and run `start` again.
